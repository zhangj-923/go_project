# 飞行棋游戏 —— 可行性方案与实现计划

## 项目背景

基于现有工作区技术栈（Go + Vue 3 + TypeScript + Gorilla WebSocket），新建独立目录 `/Users/zhang/go_project/ludo`，实现一款标准飞行棋（Aeroplane Chess）网页游戏，支持：
- 人机对战（AI 电脑玩家）
- 单机游戏（同一屏幕多人）
- 局域网联机（2-4 人实时对战）

## 游戏规则（标准版）

### 棋盘结构
- **外环跑道**：52 个公共格子，顺时针排列
- **4 个颜色区**：红 / 黄 / 蓝 / 绿，每色各有：
  - 停机坪（Hangar）：4 枚棋子起始位置
  - 起飞点（Launch Point）：1 格，进入公共跑道
  - 专属终点通道（Home Stretch）：5 格 + 中心终点
- **跳跃格（同色格）**：分布在公共跑道上，每隔约 13 格一个
- **飞行格（虚线格）**：位于每色跳跃格的特定位置，棋子落此可飞越对角

### 核心规则
| 规则 | 描述 |
|------|------|
| 起飞 | 掷出 **6点** 才能将棋子移出停机坪，并**额外投掷一次** |
| 连续6 | 连续3次掷出6点，当前棋子返回停机坪 |
| 同色跳格 | 棋子停在同色格，自动跳至下一个同色格（+13步效果） |
| 飞行（虚线）| 棋子停在特定同色格，沿虚线飞至对角同色格，可再触发跳格 |
| 吃子 | 落在敌方棋子格，敌方返回停机坪，己方**额外投掷** |
| 叠子 | 同色棋子叠放同格，形成保护盾；敌方落此，双方同格（不吃子） |
| 终点入场 | 必须精确点数进入终点通道，超出则反弹 |
| 胜利 | 最先将全部4枚棋子送达中心终点者获胜 |

## WebSocket 消息协议

所有消息统一格式：
```json
{
  "type": "MESSAGE_TYPE",
  "payload": { ... }
}
```

### 客户端 → 服务端
| type | payload | 说明 |
|------|---------|------|
| `create_room` | `{playerName, gameMode, maxPlayers, aiCount}` | 创建房间 |
| `join_room` | `{roomId, playerName}` | 加入房间 |
| `start_game` | `{}` | 房主开始游戏 |
| `roll_dice` | `{}` | 当前玩家掷骰子 |
| `move_piece` | `{pieceId}` | 选择移动哪枚棋子 |
| `leave_room` | `{}` | 离开房间 |

### 服务端 → 客户端
| type | payload | 说明 |
|------|---------|------|
| `room_joined` | `{roomId, players[], myColor}` | 成功加入房间 |
| `game_started` | `{boardState, currentTurn}` | 游戏开始 |
| `dice_rolled` | `{playerId, value, movablePieces[]}` | 骰子结果 |
| `piece_moved` | `{pieceId, from, to, events[]}` | 棋子移动（含跳格/吃子事件） |
| `turn_changed` | `{playerId, extraRoll}` | 换回合 |
| `player_joined` | `{player}` | 新玩家加入 |
| `player_left` | `{playerId}` | 玩家离开 |
| `game_over` | `{winnerId, rankings[]}` | 游戏结束 |
| `error` | `{code, message}` | 错误信息 |

## 棋盘坐标系统

使用线性索引（0-based）：
- **公共跑道**：0~51（52格）
- **红色终点通道**：100~104（5格）+ 109（中心）
- **黄色终点通道**：110~114 + 119
- **蓝色终点通道**：120~124 + 129
- **绿色终点通道**：130~134 + 139
- **停机坪**：每色4枚棋子，用 -1~-16 表示（未出飞机场）

棋盘渲染采用 **SVG**，坐标由预定义映射表生成：
```typescript
const CELL_POSITIONS: Record<number, {x: number, y: number}> = { ... }
```

## AI 策略设计

### 难度等级
| 等级 | 策略 |
|------|------|
| 简单 | 随机选择可移动棋子 |
| 普通 | 优先进攻（吃子）+ 贪心前进 |
| 困难 | 评分函数：进度分 + 安全分 + 吃子分 + 跳格期望分 |

### 困难模式评分函数
```
score(piece) = 
  progress_weight    × progress(piece)      // 越靠近终点分越高
  + attack_weight    × can_eat_enemy(piece) // 能吃子大幅加分
  + safety_weight    × safety(piece)        // 同格叠子加分
  + jump_weight      × jump_bonus(piece)    // 落在跳格/飞格加分
  + launch_weight    × should_launch(piece) // 评估是否值得出新棋子
```

## 游戏模式

### 模式一：单机游戏
- 1个真人 + 3个AI（可选2-3个AI）
- 同一浏览器窗口，真人轮到时手动操作
- AI 回合自动执行（动画可视化）

### 模式二：局域网联机
- 真人玩家通过访问同一局域网 IP 加入
- 支持 2-4 人，可补充AI填充空位
- 房间码机制（6位字母数字）
- 玩家断线后 AI 接管（30秒超时）

### 模式三：本地多人
- 同一浏览器，多人轮流操作
- 无需网络，仅前端驱动

## UI/UX 设计方案

### 视觉风格
- **主题**：现代科技感，深色底 + 荧光色高亮
- **棋盘**：SVG 绘制，四色分区清晰，格子圆角设计
- **棋子**：3D 圆柱感，有阴影，选中时有发光动画
- **骰子**：CSS 3D 翻转动画，点数清晰可读
- **配色**：
  - 背景：`#0f172a`（深蓝黑）
  - 红色区：`#ef4444`
  - 黄色区：`#eab308`  
  - 蓝色区：`#3b82f6`
  - 绿色区：`#22c55e`
  - 强调色：`#a855f7`（紫色，按钮/高亮）

### 关键交互
1. **骰子投掷**：点击骰子 → 3D滚动动画（600ms）→ 显示点数
2. **可移动棋子高亮**：骰完后，可选棋子闪烁光环
3. **棋子移动**：逐格动画移动（每格100ms），跳格有加速效果
4. **飞行动画**：弧线飞行轨迹动画（贝塞尔曲线）
5. **吃子**：被吃棋子红色闪烁后飞回停机坪
6. **胜利**：全屏烟花粒子效果 + 排名弹窗

### 响应式布局
- 桌面端：棋盘居中，两侧为玩家信息栏
- 移动端：竖屏布局，棋盘上方，玩家信息下方
